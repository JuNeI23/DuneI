# Lanceur d'applications (L2-16) — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Version 1.0 — 2026-11-19

**Objectif :** remplacer wofi par le lanceur de la coque : un accueil (médaillons fréquents, commandes suggérées) qui se
scinde en liste et aperçu dès la première lettre, avec six sources, vignettes figées et calcul par `qalc`.

**Architecture :** un module `coque/Lanceur`. La logique pure (recherche floue, classement, usage, sélection au
clavier, traduction et lecture du calcul) vit dans `lanceur.js` et `calcul.js`, éprouvés par une coque d'essai sans
fenêtre via l'IPC, comme `Applications`. Les sources produisent des résultats d'une même forme ; l'interface ne connaît
que cette forme. La fenêtre est une attention propre au lanceur (`FenetreLanceur`, plein écran, couche overlay),
inscrite dans le registre `Overlays`, qui porte un cadre redimensionné au ressort sans jamais redimensionner le calque.

**Techno :** Quickshell 0.3.2 (QML, `DesktopEntries`, `Hyprland.toplevels`, `ScreencopyView`, `Process`, `FileView`,
`IpcHandler`), libqalculate 5.13 (`qalc`), Python unittest.

**Fiche :** `docs/superpowers/specs/2026-11-19-lanceur-design.md` (v1.1, validée). Maquette de référence :
`~/dunei-atelier/maquettes/lanceur/lanceur-v3.html` (+ `lanceur-v3.css`).

## Contraintes globales

- Toute couleur vient d'un rôle de `Theme` : `color.*`, `material.*`, `glass.*`. Aucune valeur écrite en dur, même dans
  un essai.
- Tout changement visible s'anime au ressort (`Theme` : `transitions`, `motion`) ; aucun saut brut.
- Le calque `FenetreLanceur` est plein écran et ne change jamais de taille ; seul le cadre intérieur s'anime.
- Lancement par `Applications.amenerOuLancer` (`uwsm app`), jamais sous l'arbre de processus de la coque.
- Jamais `eval` ni `Function` sur la saisie ; le calcul passe par `qalc`.
- Une saisie sans chiffre n'est jamais envoyée à `qalc`.
- Rien du lanceur ne vit en mémoire quand il est fermé, sauf le relevé d'usage (`LazyLoader`).
- Chaque fonction porte l'en-tête de commentaire du projet : titre et rôle, entrées, sorties, erreurs, dépendances,
  en phrases complètes.
- Essais graphiques : `skipUnless` Wayland et `qs` ; liens `essai/` vers chaque module chargé, Barre comprise ; ne
  jamais ouvrir un overlay qui prend le clavier de Nicolas pendant qu'il travaille (sous-agents compris).
- En cours de tâche, ne lancer que les modules de test touchés ; la suite complète (`make check`) une fois avant la PR.
- Commits en français, signés `Co-Authored-By` du modèle qui les écrit ; `generated/` ne s'édite jamais.

## Points de vigilance

1. **Saisie rapide pendant que `qalc` répond** : une réponse arrivée après une nouvelle frappe ne doit jamais
   s'afficher pour la nouvelle saisie. Test dans la tâche 3 (`test_reponse_perimee_ignoree`).
2. **Fenêtre fermée pendant que le lanceur est ouvert** : sa ligne et sa vignette disparaissent sans erreur, et la
   sélection reste dans la liste. Test dans la tâche 5 (`test_fenetre_disparue`).
3. **Relevé d'usage absent, vide ou corrompu** : l'accueil se remplit tout de même (rôles, puis ordre alphabétique) et
   le fichier est réécrit sain. Test dans la tâche 2 (`test_usage_corrompu`).
4. **`qalc` absent ou mort en cours de route** : le lanceur marche sans la ligne de calcul et ne relance pas en boucle.
   Test dans la tâche 3 (`test_qalc_absent`).
5. **Saisie qui ne trouve rien** : un état vide sobre dans l'aperçu ; Entrée ne fait rien. Test dans la tâche 6
   (`test_aucun_resultat`).

## Forme d'un résultat (partagée par toutes les tâches)

```js
{
  cle: "app:org.kde.dolphin" | "fen:0x…" | "act:firefox:new-private-window" | "cmd:ne-pas-deranger" | "calc",
  genre: "application" | "fenetre" | "action" | "commande" | "calcul",
  titre: string, sousTitre: string, icone: string,   // icône freedesktop ou chemin
  type: string,           // texte gris de droite : « 3 fenêtres », « Application », « bureau 2 », « Fenêtre », « Commande », « Calcul »
  retrait: bool,          // fenêtre rangée sous son application (choix A)
  pertinence: int,        // 0 à 4, voir score()
  principale: Action, secondaires: [Action],
  apercu: { fenetres: [adresse], bureau: string, etat: string, expression: string, valeur: string }  // champs facultatifs
}
Action = { libelle: string, genre: "amener" | "lancer" | "action" | "commande" | "copier", cible: string, confirmer: bool }
```

## Structure des fichiers

| Fichier | Rôle |
| --- | --- |
| `coque/Lanceur/lanceur.js` | logique pure : score, classement, usage, fréquentes, actions visées, sélection au clavier |
| `coque/Lanceur/calcul.js` | logique pure du calcul : garde, traduction française, lecture de la sortie de `qalc` |
| `coque/Lanceur/Calcul.qml` | processus `qalc` persistant, une requête à la fois, réponses périmées ignorées |
| `coque/Lanceur/MemoireLanceur.qml` | relevé d'usage, `lanceur.json` dans `DUNEI_ETAT_DIR` ou `Quickshell.stateDir` |
| `coque/Lanceur/Sources.qml` | applications, fenêtres, actions, commandes, calcul vers des résultats |
| `coque/Lanceur/commandes.json` | commandes DuneI déclarées (hors pages de Paramètres, tirées de `Registre.pages`) |
| `coque/Lanceur/Lanceur.qml` | singleton : état (ouvert, saisie, sélection), IPC `lanceur`, exécution des actions |
| `coque/Lanceur/FenetreLanceur.qml` | attention plein écran, voile, cadre animé, accueil ou scission |
| `coque/Lanceur/Accueil.qml`, `Liste.qml`, `Apercu.qml`, `Vignette.qml`, `Plaque.qml` | vues |
| `coque/Lanceur/qmldir`, `coque/Lanceur/essai/{logique,fenetre}/` | module et coques d'essai |
| `tests/test_lanceur.py` | tous les tests du lanceur |

La sémantique de `Plaque.qml` : une seule plaque d'accent qui suit l'élément choisi (ligne, médaillon, puce, bouton,
vignette) ; elle reçoit la géométrie cible et y glisse au ressort, en s'étirant un peu pendant le trajet.

**Interfaces produites :**
- `normaliser(texte: string) -> string` : minuscules, sans diacritiques.
- `score(texte: string, saisie: string) -> int` : 4 préfixe, 3 début de mot, 2 sous-chaîne, 1 sous-séquence, 0 rien ;
  comparaison par `normaliser`.
- `pertinence(champs: [string], saisie: string) -> int` : meilleur `score` parmi les champs (nom, nom générique,
  mots-clés).
- `actionVisee(nomApp: string, nomAction: string, saisie: string) -> bool` : vrai si `score(nomAction, saisie) >= 2`, ou si
  la saisie a au moins deux mots dont le premier donne `score(nomApp, …) >= 3` et un autre `score(nomAction, …) >= 3`.
- `classer(resultats: [Resultat], poids: {cle: number}) -> [Resultat]` : calcul d'abord ; puis groupes
  d'application (une application suivie de ses fenêtres `retrait`, dans leur ordre d'usage) triés par pertinence
  décroissante, puis par poids décroissant, puis par titre ; puis actions, commandes, fenêtres isolées, sur la même
  règle.

### Tâche 3 : calcul et conversions par `qalc`

**Fichiers :** créer `coque/Lanceur/calcul.js`, `coque/Lanceur/Calcul.qml` ; modifier `paquets.toml` (ajouter
`"libqalculate",  # calcul et conversions du lanceur (L2-16)` au groupe `session`), `tests/test_lanceur.py`.

**Interfaces produites :**
- `aEnvoyer(saisie: string) -> bool` : faux sans chiffre.
- `traduire(saisie: string) -> string` : remplace « en » et « vers » (mots entiers) par `to` ; « X % de Y » par
  `X% * Y` ; préfixe la cible d'une conversion de `-`, sauf si c'est une durée (`h`, `min`, `s`, `j`, `jour`, `jours`,
  `heure`, `heures`, `seconde`, `secondes`). Les tables de mots sont des constantes exportées en tête du fichier.
- `lire(sortie: string, envoye: string) -> string` : rend `""` si la sortie est vide, commence par `error` ou
  `warning`, ou vaut l'expression envoyée à l'espace près ; sinon la sortie nettoyée des codes de couleur.
- `Calcul.qml` : `function demander(saisie: string)`, `property string expression`, `property string valeur` ("" sans
  résultat), `property bool disponible`. Un seul processus `qalc -t -s "decimal comma on" -s "color 0" -s
  "upxrates 1"` vit pendant que le lanceur est ouvert (`running` lié à `Lanceur.ouvert`) ; chaque requête porte un
  numéro, une réponse dont le numéro n'est plus le dernier est ignorée. Si `qalc` manque ou meurt, `disponible`
  passe à faux pour la durée de l'ouverture, sans relance.

  44 px ; aperçu selon la fiche (§ Scission). Les mesures sont rapportées aux jetons les plus proches ; un écart est
  signalé dans le rapport de tâche. Les éléments de l'accueil et les lignes entrent en cascade (≈ 40 ms par élément,

  et prête (pas à la création), une seule capture par ouverture ; une fenêtre disparue retire sa vignette.
