# L2-11, panneau réseau — plan d'implémentation

Version 1.0 · 2026-10-31

> **Pour les agents :** sous-compétence requise : superpowers:subagent-driven-development (recommandée) ou
> superpowers:executing-plans, tâche par tâche. Les étapes se cochent (`- [ ]`).

**But :** remplacer `nm-applet` et `nmtui` par un panneau réseau de la coque : indicateur à sept états,
popover sous l'icône, fenêtre Réseau autonome, notifications de transition.

**Architecture :** un singleton `EtatReseau` agrège `Quickshell.Networking` (connectivité, réseaux, connexion,
profils à portée) et une surveillance `nmcli monitor` unique (adresses, facturation, tous les profils, type des
connexions actives, partagé avec `Vpn.qml`). L'indicateur, le popover, la fenêtre et les notifications ne lisent
que ce singleton. L'analyse des sorties `nmcli -t` vit dans une bibliothèque JavaScript pure, testée sans réseau.

**Technologies :** Quickshell 0.3.2 (`Quickshell.Networking`, `Quickshell.Io`, `FloatingWindow`, `IpcHandler`),
NetworkManager 1.58 (`nmcli`), `notify-send` (libnotify), Phosphor 2.1.1 bold, `unittest`.

**Conception :** `docs/superpowers/specs/2026-10-31-reseau-design.md` (v1.1). Le plan s'en déduit ; les deux se
lisent ensemble.

## Contraintes globales

- Sobriété (D80) : popover et fenêtre construits à l'ouverture, détruits à la fermeture ; aucun minuteur au repos ;
  `scannerEnabled` vrai seulement popover ouvert ; un seul `nmcli monitor` dans toute la coque.
- Contrôle de connectivité : `interval=30` dans un `conf.d` système ; la coque n'interroge jamais la connectivité
  périodiquement (seul `checkConnectivity()` au retour d'un portail).
- Secret : lu seulement au clic sur l'œil (`nmcli -s -g 802-11-wireless-security.psk connection show <uuid>`),
  jamais journalisé, effacé à la fermeture de la fenêtre.
- Pas d'IP publique ; pas de VPN (sauf la lecture existante de `Vpn.qml`) ; IP fixe en IPv4 seulement.
- Notifications : `notify-send -a DuneI -h string:x-dunst-stack-tag:reseau` ; jamais de bascule automatique.
- Toute icône citée dans un QML de `coque/` figure dans `icones/correspondances.toml` (`test_icones_js_couvertes`).
- Commentaires de fonction complets (titre et rôle, entrées, sorties, erreurs, dépendances), en français accentué.
- `generated/` ne s'édite jamais : `make icones` le régénère et le commit le porte.
- Validation à l'écran par Nicolas à la fin des tâches 1, 4, 5, 6 et 7 (fenêtre réelle, `grim`).

## Points de vigilance de la relecture

1. **Noms de réseau hostiles** (deux-points, barre oblique inverse, accents, espaces, SSID vide d'un réseau
   caché) : `nmcli -t` échappe `:` et `\` ; l'analyse doit les restituer tels quels — test en tâche 2.
2. **Micro-coupures et réveil de veille** : une coupure de moins de 5 s ou la reprise après veille ne produit ni
   « perdue » ni rafale ; une seule notification par état stable — test en tâche 7.
3. **Machine sans carte Wi-Fi ou en filaire seul** : l'indicateur montre le filaire, le popover n'affiche pas de
   liste vide ni d'erreur — tests en tâches 3 et 4.
4. **Écriture refusée** (polkit, utilisateur hors `wheel`, profil verrouillé) : l'erreur de `nmcli` s'affiche
   sous le champ concerné, la valeur précédente est restaurée — test en tâche 6.
5. **Popover fermé ou détruit pendant une recherche ou une connexion** : `scannerEnabled` repasse à faux dans tous
   les cas, et un `connectionFailed` tardif ne rouvre rien — test en tâche 5.

- Tester : `tests/test_reseau.py` (nouveau), `tests/test_barre.py` (`IconesTest`)

**Interfaces :**
- Produit, dans `nmcli.js` :
  - `champs(ligne: string) -> string[]` : découpe une ligne `nmcli -t` sur les `:` non échappés et restitue `\:`
    et `\\`.
  - `lireAppareil(texte: string) -> {ip4: string[], passerelle: string, dns: string[], facture: bool}` : sortie de
    `nmcli -t -f IP4.ADDRESS,IP4.GATEWAY,IP4.DNS,GENERAL.METERED device show <iface>` ; `facture` vrai pour
    `yes` et `yes (guessed)`.
  - `lireProfils(texte: string) -> [{nom, uuid, type, appareil, actif: bool}]` : sortie de
    `nmcli -t -f NAME,UUID,TYPE,DEVICE,ACTIVE connection show`.
  - `lireProfil(texte: string) -> {autoconnect: bool, priorite: int, facture: string, methode: "auto"|"manual",
    adresse: string, passerelle: string, dns: string[], ssid: string}` : sortie de `nmcli -t -f
    connection.autoconnect,connection.autoconnect-priority,connection.metered,ipv4.method,ipv4.addresses,
    ipv4.gateway,ipv4.dns,802-11-wireless.ssid connection show <uuid>`.
  - `argsModifier(uuid: string, changes: object) -> string[]` : arguments de `nmcli connection modify` pour les
    clés `autoconnect`, `priorite`, `facture`, `methode`, `adresse`, `passerelle`, `dns`, `psk` ; refuse
    (lève `Error`) une clé inconnue ; `methode: "auto"` vide aussi adresse et passerelle.
- Produit, dans `icones.js` : `iconeReseau(e: {carte: bool, radio: bool, filaire: bool, connecte: bool,
  connectivite: string, facture: bool, force: number}) -> string`. Ordre de priorité : rien (ni carte ni filaire)
  → `""` ; filaire connecté → `network-wired` (ou `network-wired-no-route` si connectivité `limited`/`portal`) ;
  radio coupée → `network-wireless-disabled` ; non connecté → `network-wireless-offline` ; connectivité
  `limited` ou `portal` → `network-wireless-no-route` ; facturé → `network-wireless-hotspot` ; sinon les cinq
  paliers existants.
